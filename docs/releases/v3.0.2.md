# v3.0.2

This patch release fixes check-in state persistence after a restart, updates the
Python 3.14 runtime, and adds an isolated way to test compatibility with new
Pangolin releases.

## Upgrade notes

**No new breaking changes for existing v3.0.x deployments.** There are no new
environment variables, API permissions, Compose requirements, or state-file
format changes. Keep the existing persistent volume, pull the new image, and
recreate the app container. See the [upgrade guide](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.0.2/docs/upgrading.md) for the
deployment checklist, verification, and rollback.

**Upgrading from v2.x or earlier:** complete the
[v3.0.0 migration](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.0.2/docs/upgrading.md#v300-breaking-changes-upgrading-from-v2x)
first: Badger v1.4.1 or newer, **List Users** permission on the organization API
key, and a matching proxy secret in the app and Pangolin's Custom Request
Headers. These are existing v3 requirements, not new changes in this release.

## Fixed

- Fixed a restart bug where the HTTP handler retained an old state mapping after
  saved state was loaded. Check-ins now update the shared mapping used for
  persistence and cleanup. Regression checks cover loading existing records,
  writing new check-ins, and preserving state across a container restart.
  [#137](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/137),
  [#136](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/136).

  The fix cannot recover records already lost before upgrading. If you observed
  persistence problems, follow the state review guidance in the upgrade guide.

## Runtime and security

- Updated the digest-pinned Alpine runtime from Python **3.14.7 to 3.14.8**.
  Python 3.15 is not included. The host's Python installation is unaffected.
  [#136](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/136).
- Restricted container publishing to workflows initiated by the repository
  owner. Maintainers using another account must have the owner initiate image
  publication. [#128](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/128).

## Compatibility and testing

- Added a disposable Docker Compose compatibility environment that provisions
  its own Pangolin server, users, resources, and scoped API credentials. It
  checks real API behavior, authorization, rule creation and expiry, preservation
  of external rules, and state reload, then removes its temporary resources.
  It uses no production endpoints or credentials.
  [#141](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/141).
- Added a free-text `pangolin_version` workflow input accepting official release
  tags, including prereleases and an optional `v` prefix. An optional independent
  job compares the selected release with the pinned **1.24.0** baseline. These
  tests run on demand; they do not change the deployed Pangolin version.
  [#142](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/142).
- Added native **amd64 and arm64** image smoke tests for health, interpreter
  version, runtime identity, state permissions, and persistence across restart.
  Python CI now uses the exact interpreter version from the Dockerfile and
  checks submitted source without automatic formatting or style-fix PRs.
  [#136](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/136).
- Documented Pangolin 1.24 request/response headers, METHOD rule priority, cache
  behavior, and client IP considerations. Updated Ruff and Docker build actions.
  [#133](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/133).

Live API compatibility checks passed against **Pangolin 1.24.0 and
1.25.0-rc.0**; see the [recorded validation](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.0.2/docs/pangolin-compatibility.md#validation-evidence).
This covers the tested API behavior on Community/OSS images. CrowdSec, Enterprise
policies, and full Traefik/Badger SSO and OIDC authentication are outside that
suite's scope. The [testing guide](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.0.2/docs/pangolin-compatibility.md) explains coverage
and how to test another release.
