# v3.1.0

This release delivers comprehensive security, transport, concurrency, and
reliability hardening since `v3.0.1`, updates the Python 3.14 runtime, and adds
an isolated Pangolin Community and Enterprise compatibility suite.

## Upgrade notes

**No breaking configuration or schema changes for valid `v3.0.x` deployments.**
There are no new required environment variables, Pangolin API permissions, or
state-file format changes. Keep the existing persistent `/data` volume, pull the
new image once published, and recreate the app container. See the
[upgrade guide](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.1.0/docs/upgrading.md)
for the deployment checklist, verification, and rollback.

### Behavior & validation tightening (`v3.0.x` → `v3.1.0`)

Existing `v3.0.x` deployments should verify these tightened defaults and contracts
before upgrading:

- **Stricter startup configuration validation (`self_check()`):** Startup now
  exits immediately on non-integer numeric environment variables, non-positive or
  duplicate `RESOURCE_IDS`, whitespace-only `PROXY_SHARED_SECRET`, non-`https://`
  `PANGOLIN_URL`, invalid `PANGOLIN_DASHBOARD_URL`, out-of-range `LISTEN_PORT`
  (`0–65535`), `RATE_LIMIT_SECONDS < 0`, `REDIRECT_DELAY_SECONDS < 0`,
  `RETENTION_MINUTES < 1`, `CLEANUP_INTERVAL_MINUTES < 1`,
  `RULES_CACHE_TTL_SECONDS < 1`, `CROWDSEC_CACHE_TTL_SECONDS < 1`, or invalid
  `CROWDSEC_ALLOWLIST_NAME` values when CrowdSec is enabled. Secrets shorter
  than 32 characters log a startup warning.
  [#164](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/164),
  [#180](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/180),
  [#182](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/182).
- **Fail-closed `/update` JSON HTTP status codes:** Non-HTML `/update?ip=...`
  requests now return HTTP `403` on authorization denial and HTTP `502` on
  Pangolin upstream failure (instead of `200`). CrowdSec results remain additive
  inside HTTP `200` responses when Pangolin succeeds.
  [#165](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/165).
- **Outbound HTTP transport restrictions:** Pangolin API calls enforce
  `https://` matching the configured `PANGOLIN_URL` origin, reject URL
  credentials, disable HTTP redirects, ignore ambient `HTTP_PROXY`/`HTTPS_PROXY`
  environment variables, and cap response bodies at 4 MiB.
  [#163](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/163).
- **CrowdSec & optional `socket-proxy` alignment:** Host-CIDR entries
  (`ip/32` / `ip/128`) are matched and removed cleanly, startup tolerates
  Docker `/version` `403 Forbidden` responses from least-privilege socket
  proxies, and the reference `socket-proxy` service in `docker-compose.yml` is
  hardened (`PING: 1`, `read_only`, `cap_drop: [ALL]`, resource limits).
  [#180](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/180),
  [#181](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/181).

**Upgrading from `v2.x` or earlier:** complete the
[v3.0.0 migration](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.1.0/docs/upgrading.md#v300-breaking-changes-upgrading-from-v2x)
first: Badger v1.4.1 or newer, **List Users** permission on the organization API
key, and a matching proxy secret in the app and Pangolin's Custom Request
Headers. These are existing v3 requirements, not new changes in this release.

## Security & hardening

- **Bounded HTTP concurrency & graceful shutdown:** Replaced unbounded
  per-request thread spawning with `BoundedThreadingHTTPServer` (32 worker limit
  aligned with `pids_limit: 128`, returning HTTP `503` with `Retry-After: 5` on
  saturation), ensured consistent `Cache-Control: no-store` and security headers
  across responses (including `/healthz`, `/favicon.ico`, and `503`), and added
  graceful `SIGTERM`/`SIGINT` shutdown draining active workers and cleanup
  within a 4-second budget.
  [#176](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/176).
- **Header redaction, log sanitization & `/update` status codes:** Expanded
  sensitive header redaction (preserving duplicate headers), sanitized control
  characters and Unicode line separators in logged strings, and switched
  `/update` JSON failures to HTTP `403`/`502`.
  [#165](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/165).
- **HTML/template & redirect hardening:** Replaced chained template string
  replacements with single-pass `{{TOKEN}}` substitution, validated resource
  `fullDomain` host/port values before rendering action links, enforced strict
  `https://` `PANGOLIN_DASHBOARD_URL` validation on redirects and launcher rows,
  and validated `REDIRECT_DELAY_SECONDS >= 0`.
  [#164](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/164).
- **Outbound `http_json` transport hardening:** Enforced `https://` and exact
  `PANGOLIN_URL` origin matching, blocked URL userinfo, disabled redirects and
  ambient proxy environment variables, capped response reads at 4 MiB, and
  capped/sanitized logged upstream error snippets at 4 KiB without surfacing raw
  upstream bodies in runtime exceptions.
  [#163](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/163).
- **OPSEC & token scope hygiene:** Removed personal domain/org placeholder
  examples from `config.env.sample` and tests, and removed the unused
  `Update Resource Rule` token permission from documentation.
  [#157](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/157).
- **Hardened Compose `socket-proxy` reference:** Updated the optional
  `socket-proxy` example in `docker-compose.yml` with `PING: 1`, `read_only`,
  `cap_drop: [ALL]`, `no-new-privileges:true`, tmpfs/PIDs/memory limits, and a
  `/_ping` healthcheck.
  [#181](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/181).

## Bug fixes & reliability

- **IPv4-mapped IPv6 unwrapping:** Unwrapped `::ffff:a.b.c.d` addresses to
  canonical IPv4 (`a.b.c.d`) during IP extraction (`_get_real_ip()`, including
  socket fallback) and `/update?ip=...` validation so dual-stack mapped
  addresses match Pangolin `IP` rules and global-IP checks consistently.
  [#183](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/183).
- **Cleanup TOCTOU concurrency, rate-limit cache & durable state:** Added
  64-stripe per-IP locking with atomic expiration re-checks so concurrent
  check-ins renewing an IP cannot have newly created rules deleted mid-cleanup;
  keyed the rate-limit cache by `(IP, remote_user_id, remote_user)` with
  cleanup-time eviction and a 4,096-entry bound; and hardened `save_state()`
  atomic writes with `0o600` permissions and `os.fsync()`.
  [#179](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/179).
- **Pangolin connector contracts, IPv6 matching & `ruleId` deletion:** Enforced
  strict API envelope and pagination/type validation across organization user,
  role, and rule lookups; canonicalized IPv6 literals across cache, rule creation,
  and deletion matching; and persisted/targeted created `ruleId`s on deletion
  with active `IP`/`ACCEPT` fallback for legacy state entries.
  [#178](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/178).
- **CrowdSec CIDR removal, socket-proxy check & caching:** Fixed host-CIDR
  (`/32`, `/128`) detection and removal while leaving broader CIDRs untouched,
  tolerated Docker `/version` `403 Forbidden` responses in the staged startup
  connectivity check, validated allowlist names, and added cooldown/refresh
  guards.
  [#180](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/180).
- **Restart state persistence:** Fixed a bug where the HTTP handler retained an
  old state mapping after saved state was loaded; check-ins now update the shared
  mapping used for persistence and cleanup.
  [#137](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/137),
  [#136](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/136).

  The fix cannot recover records already lost before upgrading. If you observed
  persistence problems on `v3.0.1`, follow the state review guidance in the
  upgrade guide.

  (`python:3.14.10-alpine3.24`). Python 3.15 is not included. The host's Python

## Compatibility & testing

- Added a disposable Docker Compose compatibility environment that provisions
  its own Pangolin server, users, resources, and scoped API credentials,
  supports release-tag selection with optional `1.24.0` baseline comparison, and
  tests Community (`ce`) and Enterprise (`ee`) editions independently. It
  exercises real API behavior, authorization, rule creation and expiry,
  preservation of external rules, and simulated state reload without production
  endpoints or credentials.
  [#141](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/141),
  [#142](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/142),
  [#151](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/151).
- Documented Pangolin 1.24 request/response headers, HTTP `METHOD` rule
  priority, cache behavior, and client IP considerations.
  [#133](https://github.com/joe-cole1/pangolin-ip-rule-manager/pull/133).

Live API compatibility checks passed against **Pangolin 1.24.0 and 1.26.0 (both
CE and EE)** in
[run 45075014166](https://github.com/joe-cole1/pangolin-ip-rule-manager/actions/runs/45075014166);
see the
[recorded validation](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.1.0/docs/pangolin-compatibility.md#validation-evidence)
and
[testing guide](https://github.com/joe-cole1/pangolin-ip-rule-manager/blob/v3.1.0/docs/pangolin-compatibility.md)
for coverage and instructions. CrowdSec, licensed Enterprise policies, and full
Traefik/Badger SSO and OIDC authentication remain outside that automated suite's
scope.
